# Library documentation

Document installation, manual and ecosystem-specific setup, upgrades, configuration, examples, supported versions, public interfaces, compatibility, migrations, release process, and breaking-change policy.

Architecture documentation remains required even for small libraries. It may be concise, but must identify external dependencies, important runtime or build components, constraints, quality requirements, and durable decisions.

Changes to manifests, package metadata, public APIs, configuration, or compatibility declarations require a documentation-impact assessment and normally update this documentation set.
